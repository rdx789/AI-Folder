# CLAUDE.md — build conventions

- `server/` is a fixed dependency: start it and call its tools over MCP. Never edit it, never import its functions directly, and never hard-code anything about a tool's logic — discover the tools at runtime.
- Build on LangChain / LangGraph (`langchain`, `langgraph`, `langchain-mcp-adapters`), and let the adapter turn the discovered MCP tools into framework tools rather than hand-writing schemas.
- Keep the MCP SDK pinned to `mcp<2` — `langchain-mcp-adapters` doesn't support the 2.0 SDK yet, and an unpinned `pip install` will silently pull 2.x back in and break every import.
  - Blocker status (checked 2026-09-03): the cap is upstream, not ours. Latest release `langchain-mcp-adapters==0.3.2` and its `main` branch both pin `mcp>=1.24.0,<2.0.0` and still import 1.x-only paths (`mcp.server.fastmcp.*`, `mcp.client.websocket`, plain `httpx`). Forcing `mcp>=2` gives an inconsistent env + `ImportError` on `import langchain_mcp_adapters`, and the provided `server/server.py` uses 1.x `FastMCP` (and must not be edited). Work is in flight (PR langchain-ai/langchain-mcp-adapters#610) but unreleased; it's a breaking change (tool metadata camelCase→snake_case, `httpx`→`httpx2`). When a release drops the `<2.0.0` cap, bump `mcp` + `langchain-mcp-adapters` together, update `setup.sh`'s fallback pin, and re-smoke-test `mcp_client.py` and the server. Our own build code touches `mcp` only through `MultiServerMCPClient` / `get_tools()`, so it's otherwise insulated.
- Load all configuration from the environment via `load_dotenv(find_dotenv())`; never hard-code a value. If a required variable is missing, STOP and ask rather than guess. Required: `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION`, `BEDROCK_MODEL_ID`, `BEDROCK_EMBEDDING_MODEL_ID`. (No `.env.example` ships here — bring the `.env` you used elsewhere in this course.)
- Reach Bedrock through the framework's chat-model class, and keep that construction in one small function so the provider stays swappable.
- Comment only non-obvious AI/SDK decisions; leave self-evident code uncommented.
