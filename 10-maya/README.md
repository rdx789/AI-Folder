# Maya onboarding project — Milestones 1–5

Lesson 10 homework / NovaOps final-project flagship workflow. Developed as `maya/` next to the
Lesson 10 repositories and published as `10-maya/` in AI-Folder; paths below say `maya/` for
the project folder. Its source documents are included in `data/`. Run all commands from the
project folder. [`PROMPT.md`](PROMPT.md) is the build spec, reverse-engineered from this code,
for rebuilding an equivalent project from scratch.

Milestone 3 implements an executable, checkpointed LangGraph with injected model,
evidence retriever and operational read adapters. Every turn returns a typed
`OnboardingChecklist` under `result["response"]`. Milestone 4 dispatches an authorized
Webex handoff through an injected narrow port and records its typed pending result.
The homework fake performs no approval or access writes. Offline checks use fakes and local
records. Milestone 5 now provides a complete deterministic S2 replay and permission
case without Langfuse. Bedrock and MCP adapters are available for host integration.
Live Bedrock quality and live OpenSearch retrieval are evaluated separately from the
offline workflow; see "Review, hardening and verification (2026-09-30)" at the end.

## Layout

```text
maya/                 run all commands from here
  code/               the `maya` Python package: modules, server/, evals/, tests/ (tests are local, not in git)
  data/               NovaOps dataset (DATA_PATH; configurable in .env)
  results/            eval reports, logs and replay artifacts (git-ignored; regenerated by runs)
  .env  pyproject.toml  setup.sh  README.md  (REVIEW_FINDINGS.md: local review log, not in git)
```

Tools run either as package modules (`.venv/bin/python -m maya.server.server`, or the
`maya-server` / `maya-ingest` / `maya-eval` shortcuts) or by file path with the project's
interpreter (`.venv/bin/python code/server/server.py`). Use `.venv/bin/python` or activate the
venv; a system `python` without Maya installed prints a hint instead of running.

`graph.py` also runs directly, Lesson 10 style, always with the **live Bedrock model**
(`BEDROCK_MODEL_ID` and AWS credentials from `.env`; every run makes paid calls; documents are
the local `DATA_PATH` corpus with deterministic ranking). `--trace` adds the plan, reads,
sources, each model call and the graph steps. Every turn shows its tokens and running time,
and a closing line splits the run into turns, startup and other, e.g.
`12 turn(s) 43.86s (mean 3.65s, slowest 6.76s) + startup 0.43s + other 0.01s = 44.30s total`
(Python's own launch and exit, ~0.1s, happen outside the program):

```bash
.venv/bin/maya-live --session S2 --trace                 # same as: .venv/bin/python code/graph.py ...
.venv/bin/python code/graph.py --session S2 --trace       # replay S2 turn by turn, PASS/FAIL per turn
.venv/bin/python code/graph.py "Is a Webex seat available for Maya?"
.venv/bin/python code/graph.py --chat                     # interactive conversation, one thread
.venv/bin/python code/graph.py "..." --as E002/UG_REGULAR  # ask as another caller
```

Every runnable file works the same three ways: by file path (`.venv/bin/python code/graph.py`),
as a module (`.venv/bin/python -m maya.graph`), or, where listed, as a shortcut. Each accepts
`--help`, which never starts anything or makes a call.

from `pyproject.toml`, runs offline checks, and validates local data. Python 3.10+
is required. The `code/` folder is installed as the `maya` package, so imports
and `python -m maya.ingest` work from this folder without a parent repository or

reproduces the tested environment exactly: every package is pinned, including the
`setuptools` build backend so `pip install -e . --no-build-isolation` works offline, and the
final `-e .` installs Maya itself. `pyproject.toml` keeps the allowed version ranges.

`.env` is a private copy of the existing Lesson 10 configuration, with mode 600.
Backend and server configuration load this exact local file; existing environment
variables take precedence. `.env.example` documents the settings without secrets,
and `.gitignore` excludes credentials, virtual environments and generated files.
If `.env` is absent, setup creates it from the template and preserves it on reruns.
A live OpenSearch endpoint and Bedrock model access are still required for live
retrieval. Setup does not provision cloud infrastructure or index documents.

`code/server/` contains local read-only operational/policy tools and a SQLite engine using

## Milestone 2 — caller-safe evidence retrieval

Lesson 7's `02-filtering/retrieval.py` supplies the hard access and soft subject
filters. `03-reranking/retrieval.py` and `reranker.py` supply the wide candidate
search followed by a forced structured Nova scoring call. The index and ingestion
pattern comes from `01-opensearch-setup/`. We replaced classroom roles with NovaOps
user groups, added subject authorization and cited metadata, validate reranker
output, and never delete an existing index. The filter is inside `knn.vector.filter`,
as required for [efficient OpenSearch filtering](https://docs.opensearch.org/latest/vector-search/filter-search-knn/efficient-knn-filtering/).

The default adapter retrieves 20 candidates and reranks down to 4 chunks. It checks
backend hits before passing them to the reranker. `retrieve_evidence_node()` takes
`ContextPlan`, trusted runtime configuration, and an injected `EvidenceRetriever`:

```python
from maya.retrieval import retrieve_evidence_node
from maya.schemas import CallerContext, ContextPlan

# The authenticated host constructs config; never accept this from a request body.
config = {"configurable": {"caller": CallerContext("E004", "UG_HR")}}
plan = ContextPlan(
    "onboarding", subject_employee_id="E001", requires_retrieval=True,
    retrieval_query="Maya onboarding start date, location and required systems",
    required_evidence=["maya_cohen_offer_letter.md", "maya_cohen_onboarding_summary.md"],
)
result = await retrieve_evidence_node(plan, config, retriever)
```

Caller identity is not a plan field or model-visible tool argument. This module
consumes an authenticated principal; authentication itself belongs to the host.
Only HR may request another employee's evidence in this workflow. Regular employees
may retrieve documents explicitly marked for their own self-service. Group ACLs
are always applied inside the query; subject scope includes the target employee and
non-personal guidance, excluding other employees' documents. Unknown identities,
groups or unauthorized subjects produce a generic denial before embedding/search.
A denial contains no employee facts, source names, citations or missing-source list.

`required_evidence` contains source filenames, relative paths or stable source IDs.
Missing sources permit one application-generated refined query. It keeps exactly the
same ACL and subject clauses and adds an exact keyword match on the missing documents'
`source`/`source_id` (embeddings barely respond to filenames), returning the best
passage of each named document. Successful retrieval or an empty requirement list
permits no refinement; recall turns perform no retrieval. A reranker that fails or
returns an invalid ranking falls back to the vector order of the already ACL-checked
candidates; a reranker that alters or invents candidates is still rejected. Missing sources remain `unresolved`; source coverage
alone is not proof of a claim, so checklist validation separately checks extractive claim and status support.

### Corpus and access metadata

`DATA_PATH` (environment or `.env`; absolute or relative to this folder; default `data`)
selects the dataset root for every consumer: ingestion, retrieval corpus, planner source
catalogue, policy tool schemas, the MCP server and its SQLite records, and the evals.
It is resolved once in `paths.py`; `--data-root` overrides it for ingestion and the legacy
`NOVAOPS_DATA_ROOT` is used only when `DATA_PATH` is unset. Only `employment/`,
`policies/`, `it_kb/`, `contracts/` and `memos/` Markdown collections are ingested;
SQL, operational tables and other folders are excluded. Layouts with a `documents/`
parent should configure that parent as the root and supply the matching manifest.
Every source must have reviewed metadata in `access_manifest.json` (or `--manifest`).
New documents without metadata fail closed, including new contract files.

The checked-in manifest maps the local 39 source documents to audience, sensitivity,
subject employee ID, and explicit self-service permissions. Employment evidence is
HR-only at group level; single-employee offer/onboarding/access/addendum summaries
can be read by the named employee. The mixed equipment form and contractor addendum
remain HR-only. Current policies, IT-KB and memos are internal and group-readable.
This is an application-owned policy for the supplied corpus, not model inference.

Every chunk stores a root-relative source path, stable source ID, content-addressed
chunk ID, collection, audience, sensitivity, subject ID (null for general guidance)
and optional supplied date. Dates come from reviewed metadata or explicit document
`Last updated`, `Date` or `Effective date` lines; filesystem dates are never used.
Source IDs survive changes of the configured root; chunk IDs change with content.
The 250-word / 50-word-overlap splitter produces 42 chunks from the current corpus.

The local dataset contains no contract Markdown files. Contract ingestion is tested
with a fixture, but a real contract must be supplied with reviewed metadata. The
existing Webex KB and dated cleanup memo explicitly document 42 active seats against
40 licensed seats; those sources are tested as blocker evidence. A requested missing
contract remains unresolved rather than being fabricated.

## Repeat ingestion and force regeneration

```bash
maya-ingest --ingest             # Create if missing; skip if indexed evidence is unchanged.
maya-ingest --force              # Regenerate embeddings and rebuild the configured Maya index.
```

The unchanged check compares current chunk text/IDs, citation/access metadata and
vector presence/dimension against OpenSearch, plus the embedding model stored in
index mapping metadata. It does not trust local timestamps or a cached file alone.
Legacy indexes without embedding-model metadata require one forced rebuild.
`--force` implies ingestion, embeds all chunks before replacing the existing index,
and recreates it without appending duplicates. It rebuilds only the configured
`MAYA_OPENSEARCH_INDEX`; it does not delete the Serverless collection. Changed data
without `--force` returns an actionable error and preserves the existing index.

`02-filtering/{create_index,ingest,retrieval}.py`, and the Part 3 client/reranker.
We retain normalized Titan vectors, HNSW mappings, automatic Serverless storage IDs,
separate AWS credentials, collection-name endpoint resolution and cold-start timeout
handling. Lesson 7 caches subject labels only; unchanged-vector skipping and `--force`

## Milestone 3 — Maya graph

Reference comparison: `../lesson-10-context-engineering/code/03-history-distillation/`
has a 223-line graph with separate policy modules. `../lesson-10-context-engineering/SDD/03-history-distillation/`
has a 1,168-line cumulative implementation with stronger operational safeguards.
Maya follows the first version's readable graph/policy separation and adapts the
SDD version's whole-turn compression, failed-distillation retry delay, explicit tool
dependencies, checkpoint defaults and bounded tool rounds. It does not import either
lesson. The later SDD comparison adds exact acknowledgement bypass and restores
required read groups on fresh status requests even when the planner says no reads.
Maya's recall turns still expose zero schemas. Document search moves behind the injected
retriever; classroom write gates are replaced by a typed handoff.

```text
plan current turn (distill older whole turns when needed)
  -> authorize and retrieve evidence (one refinement at most)
  -> select read schemas
  -> model -> authorized reads -> model (two rounds at most)
           -> one read-only rearm if required reads were missed
  -> validate tasks and checkpoint a new dispatch attempt
  -> injected Webex port (only for a new authorized request)
  -> OnboardingChecklist with typed pending acknowledgement
```

`ainvoke` accepts only `{"newest_message": text}`. The trusted host supplies the
caller and a stable thread ID. Thread reuse by a different caller is denied before
planning or reading. The maximum recursion limit is 12; a caller may lower it.
Each turn resets read/retrieval counters. At most two read rounds fit alongside
planning, retrieval, selection, a rearm retry and finalization. The answer context
contains two recent turns; distillation covers whole older turns and preserves
exact fact/constraint values. Rejected/oversized compression retains raw history
and delays retry. That safe degradation can use more context than a successful fold.

```python
from maya.graph import Dependencies, build_graph
from maya.schemas import CallerContext
from maya.operations import LocalReadPort, MCPReadPort

# Host authenticates this principal; never copy config from an HTTP request body.
graph = build_graph(Dependencies(model, retriever, reads=LocalReadPort()))
config = {"configurable": {"thread_id": "maya-s2",
                           "caller": CallerContext("E004", "UG_HR")}}
result = await graph.ainvoke({"newest_message": user_text}, config)
checklist = result["response"]
# For a connected read-only MCP session: reads=MCPReadPort(session).
# Optional live factories: maya.model.live_model(), maya.backend.live_retriever().
```

Checklist identity/date/location and active constraints are structured fields;
`blocked_items` is a property, also included by `response_to_dict()`. Tasks retain
source/chunk citations and exact support quotes. To avoid accepting a plausible
claim with an unrelated citation, resolved descriptions must be exact excerpts
of cited evidence, with explicit status support. Paraphrases, conditional blockers,
unknown citations, missing required sources and equal-precedence conflicting task
versions remain unresolved. Webex completion is rejected. Generated free prose is
not used as a second unchecked factual output channel.

Evidence precedence for competing versions of one task: current operational records,
then Maya-specific documents, then general guidance; explicit newer source dates
break ties. Operational refresh replaces the prior snapshot. Models must return
competing versions under the same stable task ID; extractive validation is conservative
and is not a general natural-language contradiction prover. Live tests must evaluate
whether the model finds all relevant claims and competing sources.

The handoff gate checks an affirmative user command independently of the model,
requires cited Webex tasks and no unresolved work, and creates a stable typed key.
Negated, conditional and draft requests do not open it. Milestone 4 now dispatches
through the injected port and returns the acknowledged pending result; approval
belongs exclusively to the separate Webex workflow.

`code/evals/data/s2_maya.json` documents its classroom provenance. Document-search tool
expectations map to caller-safe retrieval; turn 10 expects handoff data, not a write.
`matrix.py` checks every accepted intent alternative on every turn, including both
recall turns, plus fallback read-only constraints. See `S2_TOOL_MATRIX.md`.

Milestone 3 verification originally passed 56 offline tests, including checkpointed multi-turn retention,
closed tangent projection, cached evidence on recall, authenticated subject guards,
whole-batch call validation, rearm, tool-round and recursion limits, citation forgery,
precedence/conflicts, typed pending handoff and all S2 matrix rows. No live Bedrock,

## Milestone 4 — one Webex dispatch per request

`WebexPort.request_access(WebexHandoff) -> PendingAccessResult` is the only workflow
boundary. Maya constructs `kind="webex_access"`, E001, system Webex, authenticated
caller, application-owned onboarding reason, cited evidence, and a SHA-256 key over
version/thread/caller/employee/system/reason. Turn count, wording, model prose and
changing citation IDs do not enter the key. Different threads have different keys.
The port is never a model-visible tool; only its implementation may submit the
request or carry out approvals/writes. No real implementation is included.

```python
from maya.graph import Dependencies, build_graph
from maya.ports import FakeWebexPort

fake = FakeWebexPort()
graph = build_graph(Dependencies(model, retriever, webex=fake, reads=reads))
first = await graph.ainvoke({"newest_message": turn10_text}, config)
replay = await graph.ainvoke({"newest_message": turn10_text}, config)
assert len(fake.calls) == 1
assert first["response"].pending_access == replay["response"].pending_access
assert replay["response"].pending_access.status == "pending"
```

The fake deliberately records **every invocation**, even duplicates, and returns
`WEBEX-<key prefix>` with pending status. The graph, rather than the fake, prevents
duplicate calls. Dispatch attempts and acknowledgements live in typed thread state,
separate from distilled model memory. A successful dispatch appends one typed
`webex_access` event. Replaying turn 10 or rebuilding the graph with the same
checkpointer returns the saved request ID without calling the port again.
Same-thread turns are serialized to prevent concurrent replay races in one graph.

A separate handoff node follows the checkpoint that reserves the attempt before
entering the port. One-process runtime guards also protect node retries from a
second invocation after a checkpoint-save failure. Missing port configuration,
invalid/granted results, and unacknowledged attempts are unresolved; they never
claim an acknowledged request or silently resend it. A cancelled/uncertain attempt
requires reconciliation by the host/workflow. Pending results survive later recall
and distillation, while the checklist's Webex task remains blocked. Acknowledgement
means a pending request, not granted access.

The default checkpointer is in memory: replay protection lasts while that state is
retained. Rebuilding with the same checkpointer is covered; retaining protection
across process restarts requires a durable host checkpointer. This homework does
not implement distributed transactions or a real approval workflow.

The extra dispatch node still fits the hard recursion limit of 12, including one
rearm and two read rounds. Rearm now occurs on the next model entry instead of
consuming a separate graph step.

`code/evals/data/sessions.json` is the canonical manual S2 acceptance copy. It keeps
all original non-turn-10 fields and turns verbatim, adds E004/UG_HR caller fields,
and replaces only turn 10's direct-write expectations with exactly one typed
`webex_access` handoff, pending status and forbidden `create_access_request`.
The supplied project session file was not found in the available project/lesson
locations. A provenance note makes that explicit; the fixture is not presented as
that supplied file. The matrix projection remains separate.

Verification: **73 offline tests pass** (56 existing + 17 handoff/contract tests).
Tests exercise actual LangGraph checkpoints and the non-deduplicating fake: exact
and reworded replay, simultaneous replay, new graph/same checkpoint, different
threads, pending recall after distillation, missing port, caller denial, missing

The runner adapts Lesson 10 `code/evals/runner.py`: one sequential turn loop, one
stable thread, per-turn exception capture, deterministic grading and a saved report.
It does not import lesson code or require Langfuse. `--dataset`, `--session`,

## Review, hardening and verification (2026-09-30)

A full code review followed the milestones. Its detailed log of every finding, experiment and run
(`REVIEW_FINDINGS.md`) is kept locally and is not in git; this section summarises what changed
and how to reproduce it.

### Sara's first request, on its own thread

The homework's headline request now works in one turn, not only as the twelve-turn S2 conversation:

> Prepare an evidence-backed onboarding checklist for Maya Cohen, a Customer Success
> Manager starting 2026-08-01. Include required systems, equipment, policy
> acknowledgements, and anything currently blocked.

Before, it returned only the six onboarding-database rows, with no start date or location, no
systems/equipment/policy items, and a Webex "blocked" with no reason. Now it returns 23–31
cited items from 12 sources:

- **Identity:** Customer Success Manager, 2026-08-01, Israel (from the employee record).
- **Systems:** the CSM baseline bundle (offer letter, onboarding policy).
- **Equipment:** laptop, monitor, dock and headset entitlements (offer letter, equipment policy,
  laptop runbook).
- **Policy acknowledgements:** provisioning only after the signed offer; equipment
  responsibilities; acceptable use; standard access needs manager approval.
- **Blockers:** Webex, cited to the current subscription record (42 active / 40 seats), the
  cleanup memo and the Webex runbook.

A *full checklist request* is a checklist request naming two or more sections. For it, the
application owns the plan:
- **Sources and reads:** retrieval of the checklist sources, and the reads `get_employee` →
  `list_onboarding_tasks` → `check_software_subscription`. The subscription read names the system
  from blocked access rows.
- **Scope:** rules for other audiences (contractors, privileged/admin/AWS admin access) are
  removed; every in-scope rule from the acknowledgement documents is included.

The model selects the remaining statements; claims remain exact quotes with citations. The
request is a graded case in every S2 run (`FIRST_REQUEST` in `code/evals/runner.py`).

### Other changes from the review

- **Exception handling:** two reproducible crashes fixed (an impossible date typed by the user;
  a non-ISO start date written by model memory). Malformed Bedrock/OpenSearch/MCP responses and
  bad configuration now fail with clear errors, and CLIs exit cleanly.
- **Answer grounding:** the answer model may not restate catalogue content as "unresolved".
  Planner "facts" survive only if the user said them or memory pinned them; assistant prose is
  no longer treated as a fact. Rows from a turn's required read are always included. Only the
  application closes topics.
- **Documents:** the first sentence of every Markdown section was being dropped (flattened
  headings); it is now recovered. Requirement and acknowledgement sentences can be checklist
  items. Capacity statements block only when over the limit, and a document blocker must name
  what is blocked.
- **Retrieval:** the single refinement round targets the missing named documents with an exact
  `source` filter, still inside the caller's ACL, and returns one passage per document. A
  failed reranker falls back to vector order instead of discarding the round.
- **Context size:** the conversation history stores a compact view of each answer (tasks and
  statuses) instead of the full response JSON with citations and repeated tasks.
- **Dataset root:** every file that reads the NovaOps data uses `DATA_PATH` from `paths.py`
  (previously 11 separate hard-coded paths; only ingestion was configurable).
- **Measurement:** `code/evals/metering.py` records every Bedrock call's tokens and latency by call
  site. The live runners print a token summary and save the exact requests for prompt replay
  (`code/evals/replay/`).
