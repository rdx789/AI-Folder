Maya's typed citation contract makes its answer boundary harder than SDD's prose
answer. The live baseline failed when the model paraphrased a supported claim,
changed a row status or rebuilt its citation incorrectly. `answer_context.py`
provides exact extractive statement choices with opaque IDs. The model selects
IDs; application code attaches the original citation, status and supporting quote,
then runs the existing grounding validator. Invented IDs fail closed. Comparable
monetary Finance requirements include all competing candidates automatically, so
choosing an old version cannot hide newer evidence; equal-ranked conflict remains
unresolved. This is a narrow comparator, not a general semantic contradiction engine.

The adaptation preserves Maya's stricter boundaries: authorization before planning
or retrieval, injected `EvidenceRetriever`, read-only recovery, a 12-step bound,
and exactly-once typed Webex dispatch. An evidenced explicit handoff reuses its
validated Webex support instead of retrieving or generating a second answer again.
Application code builds the typed handoff; pending approval is not evidence of
granted access. Diagnosed conflicts invalidate cached supported tasks and persist
as unresolved into summaries. It never opens an SDD-style
write gate. SDD's pruning of oldest facts/decisions was not copied: Maya's pinned
date/location/freeze and acknowledged request ledger must survive compression.

The exact acknowledgement matcher does not match “Okay, file the Webex request
now” or “Perfect. Write the full status summary”. The first-match shortcut does
not weaken caller authorization. Policy tool schemas enumerate policy stems;
memo filenames remain document-retrieval inputs, not `get_policy` arguments.

Additional repairs come from the actual live failure records: narrowly scoped
source cues correct obvious record/ticket/hardware/checklist requests when a planner
remains on the old topic. Planning is retained for contextual requests and mixed
data needs. Known read inputs are constructed from application-owned employee IDs,
the current request and schema enum; ambiguous software names are left to model
resolution. The current user request is placed last in the provider payload, after
historical context. A resolved employee record needs no model to regenerate its
identity fields, and a missing record remains unresolved.

Verification uses the unchanged manual project S2 dataset. See
`results/s2-live-model-before-sdd.json` for the 6/12 live baseline and
`results/latest-s2-live-model.json` for the replay after these changes.
Fixed document retrieval/local records/fake Webex isolate live Bedrock quality;
live OpenSearch ranking and MCP transport are outside this comparison.

pending handoff occurs at turn 10, replay adds zero calls, and unauthorized access
is denied before dependency calls. Both recall turns expose no read schemas and
perform no retrieval. Maximum 8 graph nodes remains below 12. **110 tests PASS**,
